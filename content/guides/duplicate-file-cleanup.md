# How to Clean Up Duplicate Creative Files Safely

Folders often accumulate `copy`, `new`, and `final2` files. Deleting by name alone is risky: two files with similar names may have different crops, copy, licenses, or approval status. A safer cleanup process starts by learning which files are used, then separates exact duplicates from merely similar versions.

## Make a working inventory

Choose one project folder and list the files, their sizes, modification dates, formats, and locations. Note which files appear in published pages or current documents. Do not treat “newest” as “approved.” Ask the project owner which export is in use when the answer is unclear.

Create a copy or versioned backup before changing a shared folder. For a cloud drive, confirm its recovery window and whether links point to the file's identity or its path. Recovery features vary; a backup you have checked is safer than assuming a trash folder will solve every mistake.

## Separate three cases

**Exact duplicates** have identical content, even if their names differ. A checksum can help identify them, but it does not tell you which path is linked from another document. Keep the path in active use until references are updated.

**Different exports from one source** may share a visual design but differ in dimensions, file format, color profile, compression, or transparency. These are variants, not duplicates. Label them by intended use.

**Revisions** may look similar while containing a corrected word or changed approval status. Compare them visually and read any accompanying review notes. Keep a record of the approved version before archiving old drafts.

## Move uncertain files into a review area

When you cannot prove a file is redundant, move a copy to a temporary review area with an inventory note rather than deleting it immediately. If the team confirms it is unused, archive or remove it according to the project's retention policy. For files referenced by a live website, published document, or product delivery link, update and check those references first.

For the fictional Harborfield Coffee launch, two files named `banner-final.png` might be a 1600-pixel web header and an 800-pixel email banner. Their names are poor, but both could be needed. Rename them descriptively after identifying their use; do not discard one because the previews look alike.

## Finish with a retrieval test

After cleanup, ask a colleague to find the currently approved web header, its source, and the earlier review version. If those paths are clear and links still work, the folder is in better shape. If the colleague still needs to ask which file is safe to use, improve naming and version notes before doing more deletion.
