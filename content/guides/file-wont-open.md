# What to Check When a Delivered File Will Not Open

“The file will not open” can describe several different failures. The link may be inaccessible, the download may be incomplete, the format may require another app, or the file itself may be damaged. Ask for the exact point of failure before resending the same package.

## 1. Is the problem access or opening?

If the recipient cannot reach the link, check sharing permissions, link expiration, sign-in requirements, and whether the correct address was sent. Use the recipient's access level to test when possible; a link that works for the sender may be private to the sender's account. Do not ask someone to share a password to diagnose the issue.

If the file downloads but will not open, ask for the filename, file size, app used, device type, and the error message. A screenshot of the error can help, provided it does not reveal private information the recipient does not intend to share.

## 2. Compare the delivered file with the source

Open the same delivered file on another device or app that supports the format. Compare its size with the original export. A zero-byte file or unexpectedly tiny download suggests an incomplete transfer. Re-export or re-upload from the verified source, then download it through the recipient-facing link and open that copy yourself.

Do not simply change `.svg` to `.png` in the filename. The extension should describe the actual file format. If the recipient's app cannot read the original format, make a real export in a format it accepts and explain whether editability changes.

## 3. Check archives and packaged files

If the delivery is a ZIP archive, confirm that it opens and contains the expected files. Some recipients may preview an archive without extracting it and then try to edit a file inside the preview. Give clear extraction instructions when that is relevant. If the archive is large or transferred through an unreliable route, compare the newly downloaded copy with the original and try a different delivery method if needed.

For an editable design file, check whether the recipient has the required application or account access. A flattened image may be viewable everywhere but will not provide editable layers. Be precise about what the replacement file can and cannot do.

## 4. Send a useful reply

A support response should tell the recipient what you checked and what to do next:

> I checked the download link and opened the file from a fresh download. The package contains one SVG source and one PNG export. If your app cannot open the SVG, please try the PNG for viewing. If you need to edit the artwork, tell me which app and version you use so I can check an appropriate editable export.

This is a sample response. Replace the format and test claims with what you actually verified. Do not say “the file works” when you have only opened a local source, not the delivered copy.

## Record the cause

Once resolved, note whether the issue was permissions, incomplete transfer, format mismatch, or a damaged export. If the same cause appears twice, improve the delivery checklist or product description. Good troubleshooting fixes the current file and reduces the chance of repeating the problem.
